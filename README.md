# DiscordHelper

Небольшое приложение для Windows: снимок выбранного монитора, вопрос к модели и ответ в прозрачном окне. Минималистичный интерфейс со скруглениями и собственной верхней панелью. Поддерживает OpenAI, OctavAPI и NOVA через Responses API.

## Запуск

Скачай репозиторий через **Code → Download ZIP**, распакуй и запусти `dist/DeskHost.exe`. Установка не требуется; используется .NET Framework Windows. Закрой предыдущие версии, чтобы освободить глобальные горячие клавиши. Нейтральное имя EXE, окна и описания сборки — DeskHost; процесс остаётся видимым в диспетчере задач под именем DeskHost.exe.

Открой «Настройки», выбери сервис и введи его API-ключ. Кнопка «Модели» получает доступные ID из каталога сервиса; ID также можно ввести вручную. Для снимков нужна модель с поддержкой изображений. При обычном закрытии сохраняются выбранный сервис, ID модели, вопрос и API-ключ; при следующем запуске поля восстанавливаются. Ключ записывается в `settings.json` рядом с EXE только зашифрованным через Windows DPAPI для текущей учётной записи. Вопрос и название модели хранятся обычным текстом. Перенос файла на другой компьютер или в другую учётную запись может потребовать повторного ввода ключа. При переключении сервиса предыдущий ключ не переносится. При ошибке сохранения окно остаётся открытым с сообщением об ошибке.

OctavAPI выбран по умолчанию, начальный ID модели — `gpt-6-luna`. Адрес: `https://octavapi.shop/v1/responses`. Для OpenAI: `https://api.openai.com/v1/responses`, начальная модель `gpt-4.1`. Получатель запроса отображается в настройках. Использование API оплачивается отдельно у выбранного сервиса.

### NOVA / NovaAPI

Пункт **NovaAPI** относится к сервису [NOVA / terminal](https://nova.api-node.workers.dev/), который указал владелец приложения. Это не другие одноимённые сервисы `novaapis.com` или `novaiapi.com`.

Выбери NovaAPI и вставь API-ключ NOVA из раздела подключения. Кнопка «Модели» получает доступный каталог; скрытые модели и модели без `supported_in_api` не предлагаются. Начальная модель `gpt-5.6-terra` взята из публичного скрипта сервиса. Для снимков необходимо выбрать доступную модель с поддержкой изображений.

Адреса взяты из [публичного скрипта подключения NOVA](https://nova-install-chatgpt-app.api-node.workers.dev/install.ps1), который использовался только как справочный материал и не запускался:

- Responses: `https://ru.cheapvibecode.ru/backend-api/codex/responses`.
- Модели: `https://ru.cheapvibecode.ru/backend-api/codex/models`.
- Авторизация: `Authorization: Bearer <API key>`.
- Переменная ключа: `NOVA_API_KEY`, затем `CVC_API_KEY`, если первая не задана. Ключи других сервисов не используются.

Запросы NOVA используют `stream=true`, `store=false`, инструкции и текст/изображение в формате Responses API. Первые фрагменты SSE показываются сразу, а окончательный текст подтверждается только при завершении потока. Оборванный или отменённый поток помечается «Незавершённый ответ». Ожидание можно отменить; общий срок ожидания — 120 секунд. В режиме Codex не отправляется `max_output_tokens`; фактическую длину и стоимость ответа определяет сервис, вопрос по умолчанию просит краткий ответ. Для OpenAI и OctavAPI прежний предел 800 выходных токенов сохранён.

Проверены формат запросов, разбор каталога NOVA, SSE-ответов и отмена на локальных данных. Реальный запрос с ключом NOVA и поддержка изображений конкретной моделью пока не проверены.

При запуске выбирается дисплей с максимальным числом пикселей (ширина × высота); при равенстве — первый в списке. Экран можно выбрать вручную. Видимость окна регулируется от 40 до 100%, по умолчанию — 82%.

## Скорость и качество снимка

Потоковый ответ запрашивается для всех трёх сервисов; если сервис вернул обычный JSON, он тоже поддерживается. Первый фрагмент показывается сразу, следующие объединяются не чаще раза в 80 мс, чтобы не перегружать интерфейс. Готовый ответ заменяет предварительные фрагменты. Внизу показываются время подготовки PNG, появления первого текста и общее время запроса. Измерение начинается при отправке и не включает задержку скрытия окна перед снимком. Никаких журналов с вопросами, ключами или снимками для замеров не создаётся.

Один HTTP-клиент переиспользует соединения, ключ задаётся отдельно в каждом запросе, cookies и перенаправления отключены. Подготовка JSON и обработка потока выполняются вне потока интерфейса. Тайм-ауты остаются 120 секунд для ответа и 30 секунд для каталога моделей.

Снимок по-прежнему захватывается в полном разрешении выбранного дисплея и отправляется в PNG без уменьшения, JPEG или снижения качества. Параметр изображения `detail=auto`, выбранная модель, вопрос, инструкции и ограничения ответа не менялись. Для всех трёх сервисов тест сравнил запрос с предыдущей сборкой: все поля, кроме `stream`, и PNG-байты совпали; тестовый снимок 2560×1440 сохранил разрешение. Проверены показ текста до окончания потока, замена окончательным ответом и отмена во время чтения. Ускорение реального сервиса нужно оценить по замерам: потоковый вывод позволяет раньше читать текст, а не гарантирует уменьшение времени генерации целиком.

## Горячие клавиши

Сочетания редактируются в **Настройки → Горячие клавиши**. Нажми на поле действия, введи комбинацию с Ctrl, Alt или Shift и нажми **«Применить»**. Специальное поле принимает также стрелки и комбинации, которые обычное текстовое поле использует для навигации. Tab и Shift+Tab без Ctrl/Alt остаются навигацией между полями. Во время ввода глобальные действия отключены, включая удаление приложения. Одинаковые и занятые другой программой сочетания отклоняются; при неудачном применении прежние настройки сохраняются. **«По умолчанию»** заполняет стандартные значения — затем их тоже нужно применить.

Настройки сохраняются рядом с EXE в `hotkeys.json` и загружаются при следующем запуске. Этот файл содержит сочетания и переключатель Mouse5, без API-ключа, снимков и ответов. Если папка недоступна для записи, приложение сообщает об ошибке и сохраняет прежние сочетания. При повреждённом файле используются стандартные значения.

В той же вкладке включается **«Mouse5 — снимок + отправка вместо „Вперёд“»**. По умолчанию выключено. Переключатель применяется и сохраняется сразу, независимо от кнопки «Применить» для клавиатуры. Настроенные сочетания, включая собственный Ctrl+Z, сохраняются.

При включении приложение глобально перехватывает Windows XBUTTON2: нажатие и отпускание подавляются, действие «Вперёд» не передаётся другим окнам, а один щелчок запускает тот же снимок и отправку, что основная кнопка. Ctrl не нужен. Действует также при скрытом или свёрнутом окне. Во время запроса, снимка или редактирования сочетаний Mouse5 подавляется без запуска нового действия. Удержание не создаёт повторов. При выключении настройки и после завершения приложения кнопка работает обычно; отключение посередине нажатия всё ещё подавляет его отпускание. Системные настройки мыши не меняются. Если драйвер мыши переназначает кнопку в Alt+→ или макрос, верни ей обычную функцию Mouse5/XBUTTON2.

Перехват WH_MOUSE_LL работает в отдельном потоке; внутри него нет снимков, сетевых запросов и записи настроек. Проверены синтетические события Windows: подавление обоих событий Mouse5, проход Mouse4, один запуск при удержании, пауза и восстановление после отключения/снятия перехвата. Физическую кнопку и программы со специальной обработкой ввода нужно проверить на конкретной системе.

Стандартные сочетания:

| Сочетание | Действие |
|---|---|
| Ctrl + ↑ | Новый снимок и сразу отправка вместе с вопросом |
| Ctrl + ↓ | Только новый снимок для предпросмотра |
| Ctrl + → | Отправить текущий снимок и вопрос; без снимка — только текст |
| Ctrl + Shift + ↓ | Показать или скрыть окно, вернуть после сворачивания |
| Ctrl + Shift + ↑ | Очистить сеанс, закрыться и удалить запущенную копию приложения |

**Сочетание удаления (по умолчанию Ctrl+Shift+↑) удаляет файлы без дополнительного подтверждения.** Сначала очищаются поля ключа, вопроса и ответа, освобождается снимок и отменяется локальное ожидание запроса. Буфер обмена очищается только если в нём остался текст, скопированный приложением. После закрытия скрытый процесс PowerShell удаляет точный запущенный EXE, его инструкцию `dist/README.md`, собственный `hotkeys.json` и `settings.json`, проверяя контрольные суммы. Сохранение при таком выходе не выполняется. Папка удаляется только если пустая. Соседние и изменённые файлы сохраняются. Для повторного запуска потребуется восстановить EXE из репозитория или пересобрать его.

Эта функция не удаляет исходник, старые копии, системные журналы Windows, историю буфера обмена, переменные окружения с ключами и данные на серверах. Отмена ожидания не отменяет уже выполненную обработку на сервере.

## Окно и захват

Значка на панели задач и окна в Alt+Tab нет: окно создаётся со стилем WS_EX_TOOLWINDOW без WS_EX_APPWINDOW. Эти параметры сохраняются при пересоздании окна. Для возврата окна после сворачивания используй сочетание «Показать / скрыть» (по умолчанию Ctrl+Shift+↓). Окно можно перетаскивать за верхнюю панель и менять размер за края. Собственные кнопки сворачивают, разворачивают и закрывают окно.

Весь интерфейс использует стандартный курсор-стрелку: кнопки, текстовые поля, выпадающие списки и края окна не меняют его форму при наведении. Выпадающие списки сервиса, модели и дисплея находятся внутри главного окна. У них нет отдельного верхнеуровневого окна Windows и его системной тени; режим захвата определяется главным окном. Списки поддерживают выбор мышью, Enter, Escape и Tab. ID модели по-прежнему можно вводить вручную.

При переключении скрытия открытые списки закрываются и окно со всеми дочерними элементами полностью перерисовывается. Скругления карточек, кнопок и полей отрисовываются без отдельной оконной области обрезки каждого элемента, чтобы избежать белых областей при смене режима захвата прозрачного окна. Кнопки полностью отрисовываются приложением без нативной поверхности Button, чтобы убрать обрывки рамок и углов. Физическое скругление самого окна сохранено.

Скрытие окна из захвата включено по умолчанию через Windows `SetWindowDisplayAffinity` / `WDA_EXCLUDEFROMCAPTURE`. Полное исключение поддерживается Windows 10 версии 2004 и новее. Работу необходимо проверить в нужной программе демонстрации на стороне зрителя: механизм не гарантирует скрытие при любом способе захвата.

Снимок хранится в памяти и включает весь выбранный монитор. Ctrl+↑ отправляет его сразу; для проверки предпросмотра используй раздельные снимок и отправку. Реальные ключи, снимки и ответы в этот репозиторий не включены.

## Сборка

В PowerShell из корня репозитория:

```powershell
.\build.ps1
```

Скрипт использует компилятор C# из .NET Framework Windows и создаёт `dist/DeskHost.exe`. Сторонние библиотеки не требуются.

Исходники: `src/DiscordHelper.cs`, `src/VisualControls.cs`, `src/Mouse5Shortcut.cs`, `src/UserSettings.cs`. Проверены компиляция, API-адреса и формат запросов на локальных данных, потоковый вывод, сохранение и восстановление полей с шифрованием ключа, управление окном, очистка сеанса, исключение из захвата и удаление тестовой копии после выхода. Реальные запросы с ключом и совместимость с внешними трансляциями отдельно не подтверждены. Пользовательские `hotkeys.json` и `settings.json` исключены из публикации.

Документация: [OctavAPI](https://octavapi.shop/docs/manual?tool=api), [Windows capture exclusion](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity).
